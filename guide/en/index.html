English User Guide

Use browser APIs from HTML

extended-html provides <web-socket> for WebSocket and <audio-context> for declarative Audio graphs. Both use standard JavaScript modules and need no framework or build step.

01 · Getting started

Register the element

Import the aggregate entry point once. It registers every custom element shipped by the repository. 

<script type="module">
  import "../../src/index.js";
</script>

To register only WebSocket, import src/web-socket/web-socket.js instead.

02 · Connection

Open automatically or manually

Add auto to connect when the element enters the document. Without it, query the element and call open() when ready. 

<web-socket
  id="socket"
  url="wss://echo.websocket.org"
  auto
></web-socket>
const socket = document.querySelector("#socket");
socket.open();
Removing the element from the DOM stops retry work and closes its active connection.

03 · Events

Read data from event.detail

Native open, message, error, and close events are dispatched from the element as same-named CustomEvent objects. 

<web-socket
  url="wss://echo.websocket.org"
  onopen="OnOpen(event)"
  onmessage="OnMessage(event)"
></web-socket>

<script>
  function OnMessage(event) {
    console.log(event.detail.data);
    console.log(event.detail.metadata.transport);
  }
</script>

The transport metadata is always "main" or "worker". You can also use event-handler properties or addEventListener().

04 · Methods

Control the same element from JavaScript

const socket = document.querySelector("web-socket");

socket.open();
socket.send("hello");
socket.close();

send(data) forwards supported WebSocket data unchanged. Calling it before the connection opens throws InvalidStateError. Repeated open() calls while connecting or open have no effect.

05 · Worker transport

Move connection work into a Worker

Add background to run WebSocket connection, send, close, and reconnect work in a dedicated module Worker. The public methods and events stay the same. 

<web-socket
  url="wss://echo.websocket.org"
  auto
  background
></web-socket>

Worker mode uses structured cloning without a transfer list, so a caller-owned ArrayBuffer is not detached.

06 · Fallback

Opt in to main-thread fallback

Worker startup failures emit error and do not silently change transport. Add fallback only when main-thread fallback is acceptable. 

<web-socket
  url="wss://echo.websocket.org"
  background
  fallback
></web-socket>

Fallback applies only before the Worker becomes ready. Runtime Worker failures never change transport automatically.

07 · Reconnect

Retry remote closes

Add reconnect to reconnect after a remote close. Explicit close() and DOM removal never reconnect. 

<web-socket
  url="wss://echo.websocket.org"
  auto
  reconnect
  reconnect-delay="2500"
></web-socket>

Without reconnect-delay, retries use exponential backoff: 1, 2, 4, 8, 16, then 30 seconds, capped at 30 seconds.

10 · Audio graph

Describe Web Audio with nested HTML

<audio-context> owns a declarative graph. Direct source siblings start in DOM order, deeper children form serial connections, and processor siblings fan out. Use to only to add an edge to a processor or output nested in another source tree. 

<audio-context id="audio">
  <audio-input-mic id="mic">
    <audio-biquad-filter id="mix" frequency="1200">
      <audio-output></audio-output>
    </audio-biquad-filter>
  </audio-input-mic>
  <audio-input-file id="music" src="./tone.wav" to="mix" loop>
  </audio-input-file>
</audio-context>

Audio has no auto or autoplay. Call the owning context's resume() from a user gesture to build the graph and start every source. suspend() pauses or disables them, another resume() restarts them in order, and close() permanently releases the graph. Do not start the microphone or file separately. 

const audio = document.querySelector("#audio");

start.addEventListener("click", () => audio.resume());
suspend.addEventListener("click", () => audio.suspend());
closeButton.addEventListener("click", () => audio.close());

Context, microphone, and file events share the same envelope. Read the payload from event.detail.data and graph identity from event.detail.metadata.

Gain, analyser, oscillator, delay and feedback, channel splitter and merger, compressor, convolver, panner, buffer source, media-stream destination, AudioParam automation markup, AudioWorklet, OfflineAudioContext, and microphone constraints are deferred.
