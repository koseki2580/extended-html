English User Guide

Use browser APIs from HTML

extended-html provides <web-socket> for WebSocket and <audio-context> for declarative Audio graphs. Both use standard JavaScript modules and need no framework or build step.

01 · Getting started

Register the element

Import the aggregate entry point once. It registers every custom element shipped by the repository. 

<script type="module">
  import "../../src/index.js";
</script>

To register only WebSocket, import src/web-socket/web-socket.js instead.

02 · Connection

Open automatically or manually

Add auto to connect when the element enters the document. Without it, query the element and call open() when ready. 

<web-socket
  id="socket"
  url="wss://echo.websocket.org"
  auto
></web-socket>
const socket = document.querySelector("#socket");
socket.open();
Removing the element from the DOM stops retry work and closes its active connection.

03 · Events

Read data from event.detail

Native open, message, error, and close events are dispatched from the element as same-named CustomEvent objects. 

<web-socket
  url="wss://echo.websocket.org"
  onopen="OnOpen(event)"
  onmessage="OnMessage(event)"
></web-socket>

<script>
  function OnMessage(event) {
    console.log(event.detail.data);
    console.log(event.detail.metadata.transport);
  }
</script>

The transport metadata is always "main" or "worker". You can also use event-handler properties or addEventListener().

04 · Methods

Control the same element from JavaScript

const socket = document.querySelector("web-socket");

socket.open();
socket.send("hello");
socket.close();

send(data) forwards supported WebSocket data unchanged. Calling it before the connection opens throws InvalidStateError. Repeated open() calls while connecting or open have no effect.

05 · Worker transport

Move connection work into a Worker

Add background to run WebSocket connection, send, close, and reconnect work in a dedicated module Worker. The public methods and events stay the same. 

<web-socket
  url="wss://echo.websocket.org"
  auto
  background
></web-socket>

Worker mode uses structured cloning without a transfer list, so a caller-owned ArrayBuffer is not detached.

06 · Fallback

Opt in to main-thread fallback

Worker startup failures emit error and do not silently change transport. Add fallback only when main-thread fallback is acceptable. 

<web-socket
  url="wss://echo.websocket.org"
  background
  fallback
></web-socket>

Fallback applies only before the Worker becomes ready. Runtime Worker failures never change transport automatically.

07 · Reconnect

Retry remote closes

Add reconnect to reconnect after a remote close. Explicit close() and DOM removal never reconnect. 

<web-socket
  url="wss://echo.websocket.org"
  auto
  reconnect
  reconnect-delay="2500"
></web-socket>

Without reconnect-delay, retries use exponential backoff: 1, 2, 4, 8, 16, then 30 seconds, capped at 30 seconds.

10 · Audio graph

Describe Web Audio with nested HTML

<audio-context> owns a declarative graph. Direct source siblings start in DOM order, deeper children form serial connections, and processor siblings fan out. Use to only to add an edge to a processor, physical output, or stream output nested in another source tree. 

<audio-context id="audio" sink-id="">
  <audio-input-mic id="mic" device-id="">
    <audio-biquad-filter id="mic-filter" type="highpass" frequency="120">
      <audio-output id="speaker"></audio-output>
      <audio-stream-output id="recording-output">
        <media-recorder id="recorder" timeslice="1000"></media-recorder>
      </audio-stream-output>
    </audio-biquad-filter>
  </audio-input-mic>
  <audio-input-file id="music" src="./tone.wav" loop>
    <audio-biquad-filter id="file-filter" type="lowpass"
      frequency="6000" to="speaker recording-output"></audio-biquad-filter>
  </audio-input-file>
</audio-context>

Audio has no auto or autoplay. Call the owning context's resume() from a user gesture to build the graph and start every source followed by every recorder. suspend() pauses recorders before suspending sources, another resume() restarts sources and recorders in order, and close() finalizes recorders before permanently releasing the graph. Do not start the microphone, file, or recorder separately. 

const audio = document.querySelector("#audio");

start.addEventListener("click", () => audio.resume());
suspend.addEventListener("click", () => audio.suspend());
closeButton.addEventListener("click", () => audio.close());

<audio-stream-output> converts its incoming Web Audio signal to a MediaStream. Its one direct <media-recorder> child follows the context lifecycle. Configure it with optional mime-type, audio-bits-per-second, and timeslice attributes. Use requestData() to request a chunk without ending the context-owned recording. 

const chunks = [];
recorder.addEventListener("dataavailable", (event) => {
  chunks.push(event.detail.data); // Blob
  console.log(event.detail.metadata.timecode);
});

Select one microphone on <audio-input-mic> with device-id, deviceId, or setDeviceId(). Select one physical speaker for the whole graph on <audio-context> with sink-id, sinkId, or setSinkId(). A live change connects the replacement before releasing the previous device; failure keeps the previous device and never chooses an automatic fallback. 

inputSelect.addEventListener("change", () =>
  mic.setDeviceId(inputSelect.value));

outputButton.addEventListener("click", async () => {
  const device = await navigator.mediaDevices.selectAudioOutput();
  await audio.setSinkId(device.deviceId);
});

Context, microphone, file, and recorder events share the same envelope. Read the payload from event.detail.data and graph identity from event.detail.metadata. Recorder dataavailable carries a Blob directly and adds timecode metadata. Successful live selections emit devicechange on the microphone and sinkchange on the context.

The Audio example provides copyable recipes for monitoring, recording, mixing, chunk downloads, and native MediaStream handoff. After resume(), read audio-stream-output.stream, inspect its tracks with getAudioTracks(), or pass them to standard browser APIs such as WebRTC.
