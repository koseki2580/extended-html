日本語ユーザーガイド

ブラウザAPIをHTMLで使う

extended-htmlはWebSocket用の<web-socket>と、宣言的なAudio graph用の <audio-context>を提供します。どちらも標準JavaScriptモジュールだけで動作し、 フレームワークやビルドは不要です。

01 · 導入

カスタムエレメントを登録する

集約エントリーポイントを一度importすると、リポジトリが提供するすべてのカスタムエレメントが登録されます。 

<script type="module">
  import "../../src/index.js";
</script>

WebSocketだけを登録する場合は、代わりに src/web-socket/web-socket.jsをimportします。

02 · 接続

自動または手動で接続を開く

autoを付けると、要素がDOMへ追加された時点で接続します。 付けない場合は要素を取得して、必要なタイミングでopen()を呼びます。 

<web-socket
  id="socket"
  url="wss://echo.websocket.org"
  auto
></web-socket>
const socket = document.querySelector("#socket");
socket.open();
要素をDOMから削除すると、再接続処理を停止し、開いている接続を閉じます。

03 · イベント

event.detailからデータを読む

ネイティブのopen、message、error、 closeは、同じ名前のCustomEventとして要素から通知されます。 

<web-socket
  url="wss://echo.websocket.org"
  onopen="OnOpen(event)"
  onmessage="OnMessage(event)"
></web-socket>

<script>
  function OnMessage(event) {
    console.log(event.detail.data);
    console.log(event.detail.metadata.transport);
  }
</script>

transport metadataは常に"main"または"worker"です。 イベントプロパティやaddEventListener()も利用できます。

04 · メソッド

JavaScriptから同じ要素を操作する

const socket = document.querySelector("web-socket");

socket.open();
socket.send("hello");
socket.close();

send(data)はWebSocketが対応するデータを変更せず送信します。 接続前に呼ぶとInvalidStateErrorになります。 接続中または接続済みのopen()は何もしません。

05 · Worker transport

接続処理をWorkerへ移す

backgroundを付けると、接続、送信、切断、再接続を専用module Worker内で実行します。 公開メソッドとイベントの使い方は変わりません。 

<web-socket
  url="wss://echo.websocket.org"
  auto
  background
></web-socket>

Worker modeはtransfer listを使わずstructured cloneするため、呼び出し元の ArrayBufferはdetachされません。

06 · フォールバック

main threadへの切替を明示する

Worker起動失敗はerrorで通知され、暗黙にはtransportを変更しません。 main threadへの切替を許可する場合だけfallbackを追加します。 

<web-socket
  url="wss://echo.websocket.org"
  background
  fallback
></web-socket>

フォールバックはWorkerがreadyになる前の失敗だけが対象です。 実行中のWorker障害では自動的にtransportを変更しません。

07 · 再接続

リモート切断から再接続する

reconnectを付けるとリモート切断後に再接続します。 明示的なclose()とDOMからの削除では再接続しません。 

<web-socket
  url="wss://echo.websocket.org"
  auto
  reconnect
  reconnect-delay="2500"
></web-socket>

reconnect-delayがない場合は1、2、4、8、16、30秒のexponential backoffを使い、 以後は30秒が上限です。

10 · Audio graph

ネストしたHTMLでWeb Audioを表現する

<audio-context>が宣言的なgraph全体を所有します。 直下のsource siblingはDOM順に開始し、深い子要素は直列接続、processor siblingはfan-outになります。 toは別のsource tree内にネスト済みのprocessor、物理output、または stream outputへedgeを追加する場合だけ使います。 

<audio-context id="audio" sink-id="">
  <audio-input-mic id="mic" device-id="">
    <audio-biquad-filter id="mic-filter" type="highpass" frequency="120">
      <audio-output id="speaker"></audio-output>
      <audio-stream-output id="recording-output">
        <media-recorder id="recorder" timeslice="1000"></media-recorder>
      </audio-stream-output>
    </audio-biquad-filter>
  </audio-input-mic>
  <audio-input-file id="music" src="./tone.wav" loop>
    <audio-biquad-filter id="file-filter" type="lowpass"
      frequency="6000" to="speaker recording-output"></audio-biquad-filter>
  </audio-input-file>
</audio-context>

Audioにはautoもautoplayもありません。 ユーザー操作から所有者であるcontextのresume()を呼ぶと、graphを構築し、 すべてのsource、その後にすべてのrecorderを開始します。 suspend()はrecorderをpauseしてからsourceを一時停止または無効化し、 次のresume()はsourceとrecorderを順番に再開します。 close()はrecorderをfinalizeしてからgraphを完全に解放します。 mic、file、recorderを個別には開始しません。 

const audio = document.querySelector("#audio");

start.addEventListener("click", () => audio.resume());
suspend.addEventListener("click", () => audio.suspend());
closeButton.addEventListener("click", () => audio.close());

<audio-stream-output>は入力されたWeb Audio信号を MediaStreamへ変換します。直下に1つだけ置く <media-recorder>はcontextのlifecycleに従います。 任意のmime-type、audio-bits-per-second、 timeslice属性で設定できます。context所有の録音を終了せずにchunkを 要求する場合はrequestData()を使います。 

const chunks = [];
recorder.addEventListener("dataavailable", (event) => {
  chunks.push(event.detail.data); // Blob
  console.log(event.detail.metadata.timecode);
});

microphoneは<audio-input-mic>のdevice-id、 deviceId、またはsetDeviceId()で選択します。 graph全体で使う1つの物理speakerは<audio-context>の sink-id、sinkId、またはsetSinkId()で選択します。 実行中はreplacementを接続してから以前のdeviceを解放します。失敗時は以前のdeviceを維持し、 自動fallbackは行いません。 

inputSelect.addEventListener("change", () =>
  mic.setDeviceId(inputSelect.value));

outputButton.addEventListener("click", async () => {
  const device = await navigator.mediaDevices.selectAudioOutput();
  await audio.setSinkId(device.deviceId);
});

context、microphone、file、recorderのeventは同じenvelopeを使います。 payloadはevent.detail.data、graph上の識別情報は event.detail.metadataから読み取ります。recorderの dataavailableはBlobを直接渡し、metadataへtimecodeを追加します。 実行中の選択に成功すると、 microphoneはdevicechange、contextはsinkchangeを通知します。

Audioサンプルにはmonitoring、recording、mix、chunk download、native MediaStream連携のコピーできるレシピがあります。 resume()後にaudio-stream-output.streamを読み取り、 getAudioTracks()でtrackを確認したり、WebRTCなどの標準browser APIへ 渡したりできます。

gain、analyser、oscillator、delayとfeedback、channel splitter/merger、compressor、convolver、 panner、buffer source、video recording、外部streamのrecorderへの代入、AudioParam automation markup、 AudioWorklet、OfflineAudioContext、exact device選択以外の microphone constraintsは今後の対象です。
